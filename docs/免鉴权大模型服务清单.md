## 一、结论先行

1. **最好用的替代是 Kilo Code 的 keyless 网关**——`https://api.kilo.ai/api/gateway`，模型带 `:free` 后缀免 key，200 次/小时/IP，实测 **11/15 可用**。
2. **它的免费池和 OpenCode 高度重合**（`reflection/beam-free`、`nemotron-3.5-super-vl`、`flint`、`laguna`、`north-mini-code` 等几乎是同一批）。同样的模型，OpenCode 全 429、Kilo 全通——说明 OpenCode 是把匿名额度关掉了，不是模型挂了。
3. **Pollinations 仍是稳定的零门槛兜底**，但匿名 tier 只剩 1 个模型（GPT-OSS 20B）。
4. 2026 年"免费 coding CLI"阵亡了一大片：Qwen Code 免费 OAuth（4/15 结束）、Gemini CLI 免费层（6/18 结束）、GitHub Models（关停）、Cerebras（免费转 30 天试用）、Roo Code（关闭）、Continue（停止开发）。网上的清单大多过期。

## 五、接入网关

本文列出的来源已经全部内置在 `keyless-llm` 的 `providers.json` 里（Kilo / Pollinations / BlockRun，OpenCode 默认停用）。
要加新的来源，编辑 `providers.json` 即可，不用改任何代码：

```json
{
  "id": "newsource",
  "label": "New Source",
  "base": "https://example.com/v1",
  "modelsPath": "/models",
  "freeRule": { "type": "suffix", "value": ":free" },
  "rate": "限流说明，显示在面板上",
  "enabled": true
}
```

注意两点：
- 各来源的模型 ID 命名不一致（Kilo 带 `:free` 后缀、OpenCode 是 `-free` 后缀、Pollinations 用 `tier` 字段），网关用 `freeRule` 区分，不要硬编码模型名
- Kilo 不认 `x-opencode-session`，也不需要本地注入 key；请求头保持 `Content-Type` 即可

## 六、风险与边界

- **数据可能被训练**：Kilo、Pollinations、OpenCode、多数免费层都明确写「提示词可能被记录/用于改进服务」。别把私有代码和凭据发上去。
- **额度是共享的**：200 req/h 是按 IP 的公共池，重度使用会 429；Kilo 的 `kilo-auto/free` 会自动换模型但不保证成功。
- **名单会变**：今天是 11/15，明天可能就不同。以 `/api/gateway/models` 为唯一事实来源，不要硬编码。
- **地区限制**：Kilo 不向伊朗、叙利亚、古巴、朝鲜、克里米亚等地提供服务；Pollinations 未明确排除地区。
